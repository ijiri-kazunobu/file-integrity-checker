# File Integrity Checker

SHA-256のハッシュ値を使って、フォルダ内のファイルの変更・追加・削除を検知する改ざん検知ツールです。

## 仕組み

ハッシュ値は、ファイルの中身から計算される「指紋」のような値です。同じ中身なら何度計算しても同じ値になり、1文字でも変わると全く異なる値になります。

この性質を利用し、正常な状態のハッシュ値を記録しておき（`init`）、あとで現在のハッシュ値と比較する（`check`）ことで、改ざんされたファイルを特定します。

## 使い方

```
$ python integrity.py init sample_site
$ python integrity.py check sample_site
```

| 引数 | 説明 |
|---|---|
| `command` | `init`：基準データを保存する ／ `check`：基準データと比較して改ざんを検査する |
| `folder` | 監視するフォルダのパス |

## 実行例

基準データを保存し、改ざんがない状態で検査した場合

```
$ python integrity.py init sample_site
基準データを保存しました（3 ファイル）
$ python integrity.py check sample_site
異常はありませんでした
```

ファイルの書き換え・追加・削除を行ったあとに検査した場合

```
$ python integrity.py check sample_site
[追加] evil.php
[変更] index.html
[削除] about.html
[削除] style.css
```

## 工夫した点

- **追加・変更・削除の3種類を検知**：現在のファイルを基準と比べて「追加」と「変更」を、基準のファイルを現在と比べて「削除」を検出しています。削除されたファイルは現在のファイル一覧には存在しないため、両方向から比較する必要がありました。
- **すべての削除を報告**：複数のファイルが削除された場合でも、途中で処理を止めずにすべて報告するようにしました。
- **基準データがない場合の案内**：`init` を実行する前に `check` を実行した場合、エラーで停止せず、先に `init` を実行するよう案内を表示します。
- **入力ミスの防止**：`argparse` の `choices` で、コマンドを `init` と `check` に限定しています。

## セキュリティ上の注意

基準データ（`baseline.json`）は、監視対象のフォルダの外に保存しています。同じ場所に置くと、攻撃者が改ざんと同時に基準データも書き換え、検知をすり抜けられてしまうためです。実際の運用では、基準データを攻撃者が書き換えられない別の場所に保管する必要があります。

サンプルの `sample_site` は動作確認用の架空データです。

## 今後の改善

- **サブフォルダへの対応**：現在は指定したフォルダの直下にあるファイルのみを監視しています。`Path.rglob()` を使い、サブフォルダ内のファイルも監視できるようにしたいと考えています。
- **定期的な自動実行**：タスクスケジューラや cron と組み合わせ、定期的に自動で検査できるようにしたいと考えています。

## 使用技術

- Python 3.12
- 標準ライブラリのみ（argparse、hashlib、json、pathlib）
